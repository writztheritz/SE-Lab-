# Lab 2: Agile Backlog Management and Sprint Simulation Using Jira

## Objective
Convert functional requirements from Lab 1 into Agile backlog items, simulate sprints in Jira, and analyse progress using sprint boards and burndown charts.

## Tools and Prerequisites
- Jira account
- Scrum project in Jira
- Functional requirements identified in Lab 1

## Lab Activities

### 1. Create the Product Backlog
- Organize functional requirements into Epics.
- Create User Stories under the corresponding Epics.
- Describe each User Story using the format:

  > As a [user role], I want [goal], so that [benefit].

### 2. Prioritize and Estimate
- Prioritize User Stories based on business value and user needs.
- Assign priority levels such as High, Medium, and Low.
- Estimate relative effort using Fibonacci-based Story Points.
- Use Planning Poker to discuss complexity, effort, and uncertainty.

### 3. Simulate Two Sprints
- Select backlog items for each sprint.
- Set sprint goals and dates.
- Move work items through the workflow:

  To Do → In Progress → Done

- Complete each sprint and review Epic completion.

### 4. Analyse Progress
- Review the burndown chart for each sprint.
- Compare remaining work with the planned progress.
- Identify delays, early completion, or inconsistencies.
- Reflect on estimation accuracy and team capacity.

## Submission Contents
The lab report contains:
- Jira backlog with Epics and User Stories
- Sprint boards for Sprint 1 and Sprint 2
- Sprint completion and Epic completion evidence
- Burndown charts for both sprints
- Answers to the reflection questions

## Reflection Questions
1. Did your estimations reflect the actual effort?
2. Was your backlog well-prioritized?
3. How did your simulated sprint align with your plan?
4. What insights did the burndown chart give about your team's capacity?
